# Architecture

## Selected stack

KiCad 10 + ngspice, with SKiDL as the code-first circuit definition layer
and Freerouting as an external autorouter.

## Rejected alternatives

| Alternative | Role considered | Rejected because |
|---|---|---|
| LibrePCB | PCB layout tool | No SPICE export at all — structurally incompatible with a simulate-then-layout workflow. SKiDL also has no LibrePCB output path. |
| Qucs-S | SPICE frontend / schematic capture | No headless/CLI mode found. Usable only as an optional human-facing GUI visualization layer, not automation. |
| gEDA/gaf | Schematic/PCB suite | Effectively dead (~1-2 commits/year, last stable release 2020). |
| Xyce | SPICE engine | Kept only as a possible alternate SPICE backend. ngspice is the reference engine KiCad targets and has a faster release cadence. |

These were evaluated by `toolchain-researcher`; the final selection was made
by the orchestrator based on that evidence.

## Source-of-truth strategy

The environment uses a hybrid model with a hard boundary between two kinds
of canonical data:

```
 Python / SKiDL (circuits/*.py)          .kicad_pcb
 ─────────────────────────────           ──────────
 Canonical for: TOPOLOGY                 Canonical for: LAYOUT
 (parts, values, connections)            (placement, routing, stackup)
 Version-controlled, no GUI state        Cannot be expressed in SKiDL

              │
              │  generate_netlist(tool="kicad10")
              │  generate_schematic()
              ▼
      .kicad_sch / .net    ── ONE-WAY SYNC, code → KiCad ──▶  kinet2pcb → .kicad_pcb
```

Rules that follow from this:

- Never hand-edit the generated schematic or netlist expecting it to
  survive — regenerating from `circuits/*.py` will overwrite it.
- Never treat the `.kicad_pcb` as a source of topology — it is
  layout-only, populated once from the netlist and then edited only via
  layout operations (placement, routing).
- **The SPICE netlist used for simulation is not generated by SKiDL's
  native SPICE exporter.** It is derived from the *generated schematic*
  via `kicad-cli sch export netlist --format spice`. This is a correction
  to the naive assumption that "SKiDL defines the circuit, SKiDL exports
  SPICE" — SKiDL's own `generate_netlist(tool="spice")` does not work with
  KiCad-library parts (see `docs/limitations.md` #2). The working path is:

  ```
  SKiDL circuit (circuits/*.py)
    → generate_schematic()              → .kicad_sch
    → kicad-cli sch export netlist --format spice   → .cir
    → ngspice -b                        → simulation results
  ```
